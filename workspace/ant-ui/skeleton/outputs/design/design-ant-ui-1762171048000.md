# ANT UI Browser Migration Design

## Project Overview

**Goal**: Migrate ANT UI from Electron-based desktop application to browser-based web application that communicates with ant-cli HTTP server.

**Current State**: 
- Electron app with file system access
- Direct Node.js API usage (fs, chokidar)
- Mock implementations for browser compatibility stubs

**Target State**:
- Pure browser app (React + Vite)
- HTTP/SSE communication with ant-cli server
- No Electron dependencies
- Desktop viewport only (1280px+)

## Architecture Changes

### Before (Electron-based)
```
ant-ui (Electron)
├── Main Process (Node.js)
│   └── File system access
├── Renderer Process (React)
│   └── IPC with main process
└── Preload scripts
```

### After (Browser-based)
```
ant-ui (Browser)
├── React App
│   └── HTTP/SSE client
└── API Layer
    └── Fetch + EventSource

ant-cli (Server)
└── Express + SSE
    └── Orchestrator (existing)
```

## API Integration

### Endpoints to Use

Based on the newly implemented `ExpressServerAdapter`:

1. **GET /api/projects**
   - Returns: `string[]` (project IDs)
   - Replaces: `listProjects()` stub

2. **GET /api/projects/:id/session**
   - Returns: `Session | null`
   - Replaces: `loadSession()` stub

3. **POST /api/projects/:id/execute**
   - Body: `{ task, agent?, mode?, enableEvaluation? }`
   - Returns: `{ taskId, success, message }`
   - Replaces: `executeCodeTask()` mock

4. **GET /api/tasks/:taskId/stream**
   - SSE stream
   - Returns: `LogEntry` stream
   - Replaces: Mock log generation

5. **GET /api/tasks/:taskId/status**
   - Returns: `TaskStatus`
   - For polling task completion

### Phase 2: Implement API Client Layer

**New File: `src/lib/api.ts`**

```typescript
const API_BASE = import.meta.env.VITE_API_BASE || 'http://localhost:3001/api';

export async function fetchProjects(): Promise<string[]>
export async function fetchSession(projectId: string): Promise<Session | null>
export async function executeTask(params: ExecuteParams): Promise<{ taskId: string }>
export function subscribeToLogs(taskId: string): EventSource
export async function fetchTaskStatus(taskId: string): Promise<TaskStatus>
```

**Key Design Principles:**
- Use native `fetch` API (no axios needed)
- Use `EventSource` for SSE
- Proper error handling with try/catch
- TypeScript types matching server contracts

**src/lib/session.ts:**
```typescript

  // Mock watcher

  // Or use SSE if session changes are streamed
```

**src/lib/cli.ts:**
```typescript
// Before: Mock child process
export function executeCodeTask(options) {
  return mockProcess;
}

// After: Real HTTP execution
export async function executeCodeTask(options) {
  const { taskId } = await executeTask({
    project: options.projectId,
    task: 'code',
    agent: 'architect'
  });
  
  // Subscribe to logs
  const eventSource = subscribeToLogs(taskId);
  return { taskId, eventSource };
}
```

## Component Behavior Changes

### Project Selection Flow

**Before (Electron):**
1. User selects project
2. File watcher starts
3. Reads session.json on change

**After (Browser):**
1. User selects project
2. Fetch initial session via API
3. Poll session endpoint every 2s
4. Update UI on changes

### Task Execution Flow

**Before (Electron):**
1. User clicks "Run"
2. Mock process starts
3. Mock logs generated
4. Mock completion after 500ms

**After (Browser):**
1. User clicks "Run"
2. POST /api/projects/:id/execute
3. Receive taskId
4. Subscribe to SSE /api/tasks/:taskId/stream
5. Display real-time logs
6. Poll status until completed/failed

## Non-Goals

- Mobile responsive design (desktop only)
- Offline support (requires server connection)
- Multiple server connections (single ant-cli server)
- Authentication (local development only)

## Technical Constraints

- **Browser Support**: Chrome/Firefox/Safari (latest 2 versions)
- **Viewport**: Desktop only (≥1280px width)
- **Server**: Must have ant-cli server running on localhost:3001
- **CORS**: Enabled on server side (already implemented)
- **SSE**: EventSource API (no WebSocket needed)
