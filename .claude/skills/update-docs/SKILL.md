`docs/architecture/` 문서를 코드 현황에 맞게 재구성한다. $ARGUMENTS

## 1단계: 코드 현황 파악

먼저 실제 코드를 읽어 현재 상태를 파악한다. 문서에 기록된 내용을 신뢰하지 않는다.

```bash
# 전체 소스 구조 확인
ls packages/ant-cli/src/
ls packages/ant-ui/src/
ls packages/ant-shared/src/

# 최근 변경 파악
git log --oneline -20
git diff HEAD~5 --name-only
```

## 2단계: 문서 감사 (Audit)

현재 `docs/architecture/` 문서 목록을 전수 확인하고, 각 문서에 대해 다음을 판단한다:

### 판단 기준

**제거 대상**
- 해당 코드/기능이 삭제됐거나 완전히 교체된 경우
- 내용이 다른 문서와 거의 중복되는 경우
- 너무 세부적이어서 코드 변경 때마다 유지보수가 불가능한 경우

**통합 대상**
- 두 문서가 항상 함께 참조되는 경우
- 한 문서가 너무 짧아 독립 문서로서 가치가 없는 경우
- 연관 개념이 분리되어 오히려 이해를 어렵게 하는 경우

**신규 추가 대상**
- 코드에 실제로 존재하지만 문서가 없는 중요 시스템
- 기존 문서의 범위를 벗어나 독립적으로 다뤄야 할 만큼 성장한 서브시스템

**유지 + 내용 수정**
- 구조는 맞지만 세부 내용(타입명, 경로, 흐름)이 코드와 다른 경우

## 3단계: 재구성 실행

### 문서 제거

```bash
# 제거 전: 해당 문서를 참조하는 다른 문서의 링크도 함께 제거
grep -r "removed-doc.md" docs/
# 링크 제거 후 파일 삭제
```

### 문서 통합

1. 통합 후 문서의 제목/번호/범위를 먼저 정한다
2. 두 문서의 내용을 중복 없이 합친다
3. 원본 파일 중 하나를 삭제하고, 남은 파일의 번호/이름을 정리한다
4. 다른 문서의 링크를 일괄 수정한다

### 신규 문서 추가

파일명 규칙: `{번호}-{kebab-case-topic}.md`
- 번호는 관련 문서 근처로 배치 (기존 번호 사이에 소수점 사용 가능: `05a-...`)
- 또는 전체 번호 체계를 재정렬

### 번호 재정렬이 필요한 경우

```bash
# 영향받는 모든 내부 링크 일괄 수정
grep -r "NN-old-name.md" docs/ --include="*.md" -l
```

## 4단계: 내용 작성 원칙

이 문서의 **1순위 독자는 AI 에이전트**다. 에이전트가 코딩 작업 전 컨텍스트로 주입받아, 어디에 무엇을 어떻게 써야 하는지 판단하는 데 쓴다. 사람 작업자는 2순위 독자다.

에이전트 컨텍스트로 최적화된 원칙:

**코드가 진실**
문서가 코드와 다르면 코드를 따른다. 에이전트가 잘못된 정보를 컨텍스트로 받으면 틀린 코드를 생성한다. 오래된 내용은 즉시 수정하거나 제거한다.

**"어디에, 무엇을" 중심으로 기술**
에이전트에게 필요한 것은 배경 설명이 아니라 작업 판단에 필요한 구체적 사실이다.
- 정확한 파일 경로 (`packages/ant-cli/src/composition/orchestrator.ts`)
- 정확한 타입/함수 이름 (`AdapterFactory.createMemoryAdapter()`)
- 결정 규칙 ("새 JobType 추가 시 @ant/shared → orchestrator → agent 순서로 변경")
- 제약 조건 ("환경변수는 화이트리스트 방식, `...process.env` spread 금지")

설명을 위한 설명, 역사적 배경, 이유 서술은 최소화한다.

**표와 목록 우선**
에이전트는 산문보다 표와 목록에서 구조화된 정보를 더 정확하게 추출한다.
흐름, 타입 목록, 파일-역할 매핑, 환경변수는 항상 표로 표현한다.

**코드 예시는 패턴 전달용으로만**
실제 코드는 소스 파일이 원본이다. 문서의 코드 예시는 "이 패턴을 따라라"는 지침일 때만 포함한다.

**모호한 표현 금지**
"적절히", "관련 파일을", "필요하면" 같은 표현은 에이전트가 잘못 해석한다.
항상 구체적인 파일명, 타입명, 조건을 명시한다.

**한국어 유지**
기존 문서 언어(한국어) 유지.

**경계 섹션 유지**
각 문서 말미의 `## 경계` (관련 문서 링크)는 에이전트가 추가 컨텍스트를 찾는 진입점이다. 항상 최신 파일명으로 유지한다.

**문서 집합 전체가 MECE여야 한다**

- **Mutually Exclusive**: 두 문서가 같은 내용을 기술하면 에이전트가 어느 쪽을 따라야 할지 혼란을 일으킨다. 내용이 겹치는 문서는 통합하거나, 한쪽에서 제거하고 `## 경계` 링크로 위임한다.
- **Collectively Exhaustive**: 코드에 존재하지만 어떤 문서에도 기술되지 않은 중요 시스템은 에이전트의 사각지대가 된다. 문서 감사(2단계) 시 누락 영역을 반드시 확인하고 신규 문서를 추가한다.

MECE 위반 패턴:
- 두 문서에 같은 타입/함수/흐름이 중복 기술됨 → 한 곳에만 두고 나머지는 링크
- 한 문서가 다른 문서의 내용을 "요약"하는 형태로 중복 → 요약 제거, 링크로 대체
- 중요한 서브시스템이 기존 문서의 한 단락으로만 언급됨 → 독립 문서로 분리 검토

## 5단계: 일관성 검증

```bash
# 모든 내부 링크가 실제 파일로 존재하는지 확인
grep -r "\.md)" docs/architecture/ --include="*.md" -o | sed 's/.*(\(.*\))/\1/' | sort -u
ls docs/architecture/
```

깨진 링크가 있으면 모두 수정하고 완료한다.
