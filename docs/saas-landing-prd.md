# PRD — ANT Works AutoDev Landing Page  
*(Frontend-Only, Design-System + App Architecture Required)*

본 문서는 ANT Works AutoDev 엔진이 자동으로 생성할 **프론트엔드 랜딩 페이지**의 요구사항을 기술한다.  
모든 UI는 공통 디자인 시스템에 기반해 생성되며,  
**현존하는 정식 애플리케이션 아키텍처(예: Clean Architecture, Layered Architecture 등) 중 하나를 선택하고 이를 준수하여 개발**해야 한다.

이 문서는 “폴더 구조를 정하라”는 의미가 아니라  
**앱 전체를 특정 아키텍처 패턴에 따라 책임/레이어를 분리하고, 역할을 구분하여 구현하라**는 의미이다.

---

# 1. 목적 (Purpose)

- ANT Works AutoDev가 “PRD → 시스템 설계 → 아키텍처 선택 → UI 컴포넌트 생성 → 완성된 페이지 출력”까지  
  **전체 자동 생성 프로세스를 수행함**을 보여주는 데모 제작.
- 프론트엔드 단일 랜딩 페이지를 자동으로 생성하는 기능을 시각적·구조적으로 증명.
- 임의의 UI를 빠르게 만드는 것이 아니라,  
  **공통 디자인 시스템 + 정식 앱 아키텍처 위에서 자동화**가 가능함을 증명하는 것이 목적.

---

# 2. 산출물 (Deliverable)

- React 또는 Next.js 기반의 단일 랜딩 페이지
- **선택된 앱 아키텍처 패턴을 준수한 구조(의존성 규칙 포함)**  
- **디자인 시스템 기반 UI 컴포넌트 세트 포함**
- 반응형 UI (모바일/데스크톱)
- 푸터에 자동 생성 문구 포함:  
  **“This page was auto-generated by ANT Works.”**
- mock 데이터 기반, 백엔드 없음

---

# 3. 디자인 시스템 요구사항 (Design System Requirements)

### 3.1 모든 UI는 공통 디자인 시스템을 따르며, **재사용 가능한 UI 컴포넌트들로만 구성**해야 한다.
예시(권장):
- Button (variant/size 지원)
- Card
- Input
- SectionTitle
- SubTitle
- Container
- Icon Wrapper
- Spacer
- Typography presets  
- Color tokens / spacing tokens / radius tokens 등

### 3.2 스타일 요구사항
- TailwindCSS + 토큰 시스템 기반  
- 다크모드 optional  
- UI 컴포넌트는 반드시 구조적으로 재사용 가능하게 작성  
- 하드코딩된 inline style 금지

---

# 4. 앱 아키텍처 요구사항 (App Architecture Requirements)

이 프로젝트는 단순 컴포넌트 나열이 아니라  
**정식 아키텍처 패턴을 선택하여 준수하는 프론트엔드 애플리케이션이어야 한다.**

아키텍처 패턴은 아래 중 하나를 사용한다:

### ✔ Clean Architecture (추천)  
### ✔ Layered Architecture (Presentation / Domain / Application)  
### ✔ Component-driven Architecture  
### ✔ Atomic Design Architecture  
### ✔ Frontend Hexagonal Architecture  
(위 중 하나를 AutoDev가 자동으로 선택하고 문서화해야 함)

### 4.1 필수 규칙  
선택한 아키텍처 패턴에 따라 다음을 준수해야 한다:

1. **레이어/책임 분리**  
   - UI(Presentation)  
   - Domain (로직/모델)  
   - Application (상태/흐름)  
   - Infrastructure(optional)

2. **레이어간 의존성 규칙 준수**  
   - 상위 레이어는 하위 세부 구현에 직접 의존하지 않음  
   - UI → Domain 직접 침범 금지 (패턴에 따라 다름)

3. **컴포넌트는 아키텍처 역할에 맞게 배치**  
   - 단순히 폴더만 맞추는 것이 아니라  
     *역할 기반 책임 분리*가 되어야 함.

4. **아키텍처 선택 이유 및 설계 출력 필요**  
   - AutoDev는 왜 그 아키텍처를 선택했는지 설명을 포함해야 함  
   - 각 레이어에 어떤 역할이 구현되는지 자동 문서화

📌 **이 요구사항의 핵심은 “폴더 구조”가 아니라 “앱의 책임/의존성 규칙을 갖춘 아키텍처 기반의 코드”를 생성하는 것이다.**

# 6. 기술 요구사항 (Tech Requirements)

### 필수
- React 또는 Next.js  
- TypeScript  
- TailwindCSS  
- 선택된 아키텍처 패턴 기반의 역할 분리  
- UI는 디자인 시스템 기반  
- mock 데이터로 동작

### 불필요
- 서버/API/DB  
- 상태관리 라이브러리(필요할 경우 minimal state만)

---

# 7. 데모 시나리오 (Demo Flow)

1. 이 PRD를 AutoDev에 입력한다  
2. AutoDev가 **앱 아키텍처 패턴을 선택**하고 이유 포함 설계 출력  
3. 공통 UI 디자인 시스템 설계 출력  
4. 각 레이어별 역할 분리 기반 컴포넌트 설계  
5. 코드 자동 생성  
6. 빌드 및 프리뷰 표시  
7. Footer에서 자동 생성 문구 확인  
8. “PRD → 설계 → 아키텍처 → UI 생성 → 완성된 페이지” 전 과정이 자동화되었음을 시연

# 9. 비고

- 이 PRD는 **AutoDev 엔진이 실제로 아키텍처 기반 프론트엔드 애플리케이션을 자동 생성할 수 있는지 검증하기 위한 문서**이다.  
- “폴더 구조를 지정하라”는 뜻이 아니라,  
  **Clean / Layered / Hexagonal / Atomic 등 정식 아키텍처 패턴을 선택하고 구조적으로 준수하라**는 의미다.  
- 모든 컴포넌트는 디자인 시스템을 준수한 공통 UI 기반으로 만들어야 한다.
