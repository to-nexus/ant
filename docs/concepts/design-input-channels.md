# Design input channels

Ant accepts **three first-class design sources**. The choice matters
because each has a different interpretation contract — the prompts,
artifact policies, and verification rules differ.

The SSOT for hard-exclusive enforcement is `normalizeUiSourceRefs` in
[`packages/ant-shared/src/canonical.ts`](../../packages/ant-shared/src/canonical.ts).
The binding rules live in
[AGENTS.md § UiSource](../../AGENTS.md#uisource--three-hard-exclusive-ui-inputs).

## The three sources

| Source    | Path                          | What you drop                        | Interpretation contract                        |
|-----------|-------------------------------|--------------------------------------|------------------------------------------------|
| `ant`     | `visual/ui/ant/`              | `ui-tokens.json`, `ui-spec.json`, `ui-assets.json` (auto-generated by the design job) | Schema-based: tokens are reusable design primitives, spec defines layout intent. |
| `figma`   | `visual/ui/figma/figma.json` | Just a Figma URL + nodeId            | Live MCP exploration: the agent fetches frames, variables, and styles at prompt time. |
| `handoff` | `visual/ui/handoff/**`        | Free-form bundle (HTML/CSS/MD/PNG/JSON) | Observation-only (FPOP): the agent inspects what is observable and does not infer schema. |

These three are **hard-exclusive per workspace**. Mixing them in a single
RAC throws an exception at the safety net layer
(`ArtifactPoolView.uiSource()` and `validateUiSourceExclusivity`).

## Why three sources?

Different design provenance, different best practice for using it.

### `handoff` — Claude artifacts and similar bundles

This is often the lowest-friction entry point. You've been iterating on a
UI design in Claude.ai or another LLM workspace, and you have:

- HTML/CSS/Markdown describing what you want.
- Maybe a screenshot or two.
- Maybe a JSON dump of design tokens.

You drop the bundle into `visual/ui/handoff/` and Ant treats it as
**observable-only** design source. The prompt explicitly tells the agent:

> Inspect what you can observe. Do NOT infer a schema. Do NOT assume tokens
> are reusable across contexts unless the input declares them as such.

This is FPOP ("First-Principles Observation Prompting") in action. It
preserves the messiness of free-form input without pretending it's
canonical. You don't need a Figma license. You don't need to convert
anything. You just drop the files.

The handoff source is most valuable when **the design lives in a different
tool** and you don't want to translate it.

### `figma` — Bidirectional Figma MCP

When you have a Figma project, the right move is to point Ant at it and
let the agent fetch what it needs **at prompt time**. The
`visual/ui/figma/figma.json` file is just metadata:

```json
{
  "url": "https://www.figma.com/design/<fileKey>/...",
  "nodeId": "1:23"
}
```

The Figma MCP (desktop in local mode, HTTP bridge in cloud mode) handles
discovery: variables, styles, frame trees, component instances. The agent
issues `get_design_context`, `get_screenshot`, `get_metadata` calls as
needed.

You also get the reverse direction: design jobs can write back to Figma
via `use_figma` (the canvas write tool), and Code Connect mappings keep
component instances aligned with code.

### `ant` — Generated tokens and spec

For a greenfield project (no existing design system), you ask Ant to
**generate** the design system itself. The design job (`design` jobtype)
runs with one of:

- `gen-ui-figma` if you have a Figma reference.
- `gen-ui-desc` if you have a textual description.

It produces `ui-tokens.json` (palette, spacing, type scale, radii, shadows),
`ui-spec.json` (sections + components), and `ui-assets.json` (asset
catalog).

Subsequent code jobs read these as **schema-based** authoritative inputs.
The token names are stable across tasks; the spec defines layout intent.

## How the agent picks a source

It doesn't. **You** pick by populating the RAC with one of the three
slots:

| RAC slot                              | Resolved UiSource |
|---------------------------------------|-------------------|
| `visual/ui/ant/**` is in `refs` or `context` | `ant`        |
| `visual/ui/figma/figma.json` is in `refs` or `context` | `figma` |
| `visual/ui/handoff/**` is in `refs` or `context` | `handoff` |

The frontend wizard helps you pick the right slot. The backend's
`normalizeUiSourceRefs` enforces hard-exclusivity at every RAC-creating
site.

If your workspace happens to have multiple sources on disk, the
`pickDefaultUiSourceRefs` helper picks the highest-priority one (priority
order: `UI_SOURCE_PRIORITY` in `canonical.ts`). For a custom flow, edit
the RAC explicitly.

## What the prompt does per source

| Phase             | `ant`                                      | `figma`                                  | `handoff`                                |
|-------------------|--------------------------------------------|------------------------------------------|------------------------------------------|
| `code.decompose`  | Inventory tokens; ladder design-system tasks | List Figma tools; live-fetch on demand  | Observe the bundle; no schema inference  |
| `code.plan`       | Map tokens → component classes              | Fetch frame layouts; map Figma variables to tokens | Read what's observable; respect the input as-is |
| `code.execute`    | Apply tokens by name                         | Fetch styles; respect figma vs code drift| Match the bundle's vocabulary           |

Each pathway is wired by a per-source partial under
`templates/jobs/code/base/injections/`:

- `ui-source-ant.md`
- `ui-source-figma.md`
- `ui-source-handoff.md`

The `ui-source-dispatch` partial selects the right one at render time.

## The game domain mirror

Game projects use `visual/game-art/` instead of `visual/ui/`. The
sub-source structure mirrors UI: `ant/` is the LLM-generated canonical
sub-source (`game-art-tokens.json`, `game-art-assets.json`,
`game-art-spec.json`). `figma/` and `handoff/` are reserved for Phase 5+.

The `gameArtTier` and `visualTier` are vertically split (D28): a service
project never has a `gameArtTier`, and a game project never has a
`visualTier`. See [AGENTS.md § Domain-Surface Boundary](../../AGENTS.md)
for the matrix gate.
