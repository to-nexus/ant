01

제품 개요

단순 코드 생성기가 아닌, PRD → Design Spec(JSON) → Code가 Spec을 소비하는 구조화된 AI 소프트웨어 개발 프로세스 도구.

⚙

Hexagonal Architecture

4-Process 분산 모델 (API / Realtime / Job Worker / Preview). Redis + BullMQ 프로세스 간 통신.

⚡

LangGraph 에이전트

7단계 상태 머신: triage → detect → decompose → plan → execute → enforce → learn.

☁

클라우드 운영 중

K8s 배포 + CI/CD (ECR, S3, CloudFront) 가동. 로컬 = 클라우드 동일 코드 경로.

06

실행 로드맵

Phase 0 · 1-2개월
안정화 + 공개 준비
  • 핵심 파이프라인 안정화, 버그 수정, 엣지케이스 처리
  • 주요 경로 통합 테스트 추가
  • 시크릿/내부 설정 분리
  • docker-compose 로컬 실행 가이드 (원커맨드 부팅)
  • 스크린샷/데모 GIF 제작, README 정비
  • CONTRIBUTING.md, LICENSE(AGPL-3.0) 추가
Phase 1 · 2-6개월차
공개 + 클라우드 무료 베타
  • GitHub 공개 + Product Hunt / HN / Reddit 론칭
  • 클라우드 무료 tier 오픈 (LLM 크레딧 제한)
  • 커뮤니티 피드백 기반 빠른 이터레이션
  • 초기 기여자 온보딩
Phase 2 · 6-10개월차
유료화
  • Pro / Enterprise 과금 시작
  • 테스트 커버리지 대폭 보강 (SLA 준비)
  • 팀 기능 강화 (멀티테넌트, 공유 워크스페이스)
Phase 3 · 10-18개월차
스케일
  • 플러그인/통합 시스템
  • 커뮤니티 프롬프트 템플릿
  • 사용 패턴 기반 프롬프트 최적화 (데이터 해자)
  • Enterprise 영업 시작
07

리스크

🔒

포크/복제

AGPL이 SaaS 포크를 방지. 대기업 내부 사용은 가능하나, 인프라 복잡도와 업데이트 부담이 자연 억제력.

👤

단독 개발 병목

현재 1인 개발 체제. 커뮤니티 기여가 보완 가능하나 코어 결정은 병목. Phase 1 이후 팀 충원이 성장 속도 좌우.

💬

커뮤니티 관리 부담

이슈, PR 리뷰, 문서화에 시간 소요. 초기에는 코어 개발 속도와 트레이드오프.

⭐

초기 견인력 불확실

데모/스크린샷 품질과 론칭 채널 전략이 GitHub star와 초기 사용자를 좌우. Phase 0의 데모 제작이 핵심.
