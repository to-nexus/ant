# Ant 제품 전략 보고서: 오픈소스 + 클라우드 병행

---

## 1. 제품 개요

Ant는 AI 기반 소프트웨어 개발 프로세스 도구다. "프롬프트를 넣으면 코드가 나오는" 단순 생성기가 아니라, **PRD -> Design Spec(JSON) -> Code가 Spec을 소비**하는 구조화된 파이프라인을 제공한다.

**핵심 파이프라인**: plan -> design -> code -> learn -> ask (6개 JobType)

**아키텍처**: Hexagonal Architecture 기반 4-Process 분산 모델(API / Realtime / Job Worker / Preview). Redis/BullMQ로 프로세스 간 통신하며, 로컬과 클라우드가 동일 코드 경로를 탄다. K8s 클라우드 배포 및 CI/CD 운영 중.

---

## 2. 기술 경쟁력

### 2-1. 경쟁 제품 대비 포지션

5개 축으로 평가. Cursor/Devin/Lovable은 소스 비공개로 외부 분석 기반 추정(*).

```
              설계구조  에이전트  인프라   코드품질  LLM통합
Cursor*         A        A       S       A*       S
Devin*          A        S       A*      A*       S
Lovable*        B+       B+      A       B+*      B+
Ant             B+       A-      B+      B-       B+
Bolt.new        C        C       B       C+       B
```

**Ant의 위치**: 에이전트 정교함(A-)이 핵심 강점. LangGraph 기반 7단계 상태 머신(triage/detect/decompose/plan/execute/enforce/learn), TaskOrchestrator(exclusive/barrier/parallelGroup/priority)로 Lovable/Bolt 대비 확실한 우위. Cursor/Devin과의 격차는 주로 인프라 스케일과 커스텀 모델 부재에서 발생하며, 이는 팀 규모와 자본의 차이.

### 2-2. 경쟁사에 없는 차별화

- **plan -> design -> code 파이프라인**: 중간 설계 산출물(ui-tokens/assets/spec JSON)을 코드가 계약으로 소비하는 구조. Cursor/Copilot은 설계 단계 없음, Lovable/Bolt은 중간 산출물 없이 즉시 생성
- **Figma 탐색 -> 구조화 디자인 태스크 분해**
- **4-Process 분산 아키텍처에서 로컬=클라우드 동일 경로**

### 2-3. 보완 필요 영역

- **테스트 커버리지**: 백엔드 8개, 프론트엔드 0개. 아키텍처 구조(hexagonal)가 변경 파급을 제한하지만, SLA 보장을 위해서는 통합/e2e 테스트 보강 필요
- **타입 안전성**: LangGraph 그래프 정의의 `as any` 패턴 정리 필요

## 4. 전략: 풀 오픈소스 + 클라우드 서비스 병행

### 4-1. 왜 풀 오픈소스인가

**ant-cli + ant-ui + ant-shared 전체를 공개**한다. 백엔드만 공개하는 것은 전략적으로 의미가 없다. `ant-cli`는 CLI 도구가 아니라 4-Process 백엔드 서버이며, Ant의 가치는 시각적 파이프라인(칸반, 워크플로 그래프, 채팅, 실시간 진행, 프리뷰)에서 체감된다. 스크린샷과 데모가 GitHub 첫인상이 되어야 한다.

**선례**:
- Bolt.new: UI 전체 포함 오픈소스 -> $40M ARR in 5개월
- Supabase: Studio(관리 UI) 포함 오픈소스 -> $100M ARR
- n8n: 워크플로 UI 전체 오픈소스 -> 클라우드 유료 서비스 수익화

### 4-2. 자연 해자 구조

오픈소스 프로젝트에서 셀프호스팅 사용자의 5-15%만 장기 운영. 나머지는 관리형 서비스로 전환한다.

**해자 3중 구조**:

1. **인프라 복잡도**: Redis + 4개 프로세스 + BullMQ + IDE 오케스트레이션 + Preview Service + ChromaDB. 일반 개발자가 프로덕션 수준으로 운영하기 매우 어려움
2. **LLM 비용**: 셀프호스팅해도 LLM API 비용은 사용자 부담. 클라우드가 볼륨 디스카운트로 더 싼 가격 제공 가능
3. **지속적 업데이트**: AI 도구는 모델 변경, 프롬프트 최적화가 지속적으로 필요. 셀프호스팅은 업데이트 부담이 큼

### 4-3. 라이선스

**AGPL-3.0**. SaaS로 제공 시 소스 공개 의무가 발생하므로 경쟁사의 포크 후 비공개 SaaS화를 방지한다. Supabase, Grafana가 동일 모델.

## 5. 수익 모델 및 매출 추정

### 5-1. 가격 체계

- **무료 tier**: LLM 크레딧 제한, 개인 사용
- **Pro** (월 $25): LLM 크레딧 증가, 팀 기능
- **Enterprise** (커스텀, 월 $100+/seat): SSO, 감사 로그, 전용 지원, SLA

### 5-2. 매출 추정

현재 프로젝트 전담 1명(풀스택 임원급), 회사 전체 70명(개발 30-40명). DevOps 인프라 지원은 받고 있으나 제품 개발 리소스는 제한적. 이를 전제로 3개 시나리오를 추정한다.

## 6. 실행 로드맵

### Phase 0: 안정화 + 공개 준비 (1-2개월)

아직 개발 중인 기능 완성, 버그 수정, 테스트 보강이 우선.

- 핵심 파이프라인(plan/design/code/learn/ask) 안정화 및 엣지케이스 수정
- 주요 경로 통합 테스트 추가
- 시크릿/내부 설정 분리
- docker-compose 기반 로컬 실행 가이드 (원커맨드 부팅)
- 스크린샷/데모 GIF 제작
- CONTRIBUTING.md, LICENSE(AGPL-3.0) 추가
- README 정비 (아키텍처 다이어그램, 퀵스타트, 스크린샷)

### Phase 1: 공개 + 클라우드 무료 베타 (2-6개월차)

- GitHub 공개 + Product Hunt / Hacker News / Reddit 론칭
- 클라우드 무료 tier 오픈 (LLM 크레딧 제한)
- 커뮤니티 피드백 기반 빠른 이터레이션
- 초기 기여자 온보딩

### Phase 2: 유료화 (6-10개월차)

- Pro / Enterprise 과금 시작
- 테스트 커버리지 대폭 보강 (SLA 준비)
- 팀 기능(멀티테넌트, 공유 워크스페이스) 강화

### Phase 3: 스케일 (10-18개월차)

- 플러그인/통합 시스템
- 커뮤니티 프롬프트 템플릿
- 익명 사용 패턴 기반 프롬프트 최적화 (데이터 해자)
- Enterprise 영업 시작

## 7. 리스크

- **포크/복제**: AGPL이 SaaS 포크를 방지하나, 대기업 내부 사용은 막을 수 없음. 인프라 복잡도와 업데이트 부담이 자연 억제력
- **단독 개발 병목**: 현재 1인 개발 체제. 커뮤니티 기여가 이를 보완할 수 있으나, 코어 아키텍처 결정은 여전히 병목. Phase 1 이후 팀 충원이 성장 속도를 좌우
- **커뮤니티 관리 부담**: 이슈, PR 리뷰, 문서화에 시간 소요. 초기에는 코어 개발 속도와 트레이드오프
- **GitHub star 확보 불확실성**: 스크린샷/데모 품질과 론칭 채널 전략이 초기 견인력을 좌우. Phase 0의 데모 제작이 전략 성패의 핵심
