# PRD: TaskFlow

---

## 1. 요약

팀 협업용 태스크 관리 웹 애플리케이션. 프로젝트별 태스크 생성·할당·추적, 실시간 알림, 대시보드 통계를 제공한다.

---

## 2. 문제 / 목표

### 목표
- 팀원이 태스크를 생성하고, 다른 팀원에게 할당하며, 상태(Todo/In Progress/Done)를 변경할 수 있는 웹 인터페이스를 제공한다.
- 프로젝트 단위로 태스크를 그룹화하여 관리할 수 있도록 한다.
- 태스크 상태 변경 시 할당된 팀원에게 인앱 알림을 전달한다.
- 프로젝트별 진행률과 멤버별 태스크 통계를 대시보드에서 확인할 수 있도록 한다.

### 비목표 (Non-Goals)
- 파일 첨부 및 문서 관리
- 타임라인/간트차트 뷰
- 외부 서비스 연동 (Slack, Jira 등)
- 모바일 네이티브 앱
- 결제/구독 시스템

---

## 3. 사용자 시나리오

### 시나리오 1 — 회원가입 및 로그인
1. 사용자가 이메일과 비밀번호로 회원가입한다.
2. 이메일 인증 후 로그인하여 대시보드에 접근한다.
3. 로그인 상태는 JWT로 유지된다.

### 시나리오 2 — 프로젝트 생성 및 멤버 초대
1. 사용자가 새 프로젝트를 생성하고 이름과 설명을 입력한다.
2. 이메일 주소로 팀원을 초대한다.
3. 초대받은 팀원은 알림을 통해 프로젝트에 참여한다.

### 시나리오 3 — 태스크 생성 및 할당
1. 프로젝트 내에서 새 태스크를 생성한다. 제목, 설명, 우선순위(Low/Medium/High), 마감일을 입력한다.
2. 태스크를 특정 멤버에게 할당한다.
3. 할당된 멤버는 인앱 알림을 받는다.

### 시나리오 4 — 태스크 상태 관리
1. 칸반 보드에서 태스크를 드래그앤드롭으로 상태를 변경한다 (Todo → In Progress → Done).
2. 상태 변경 시 프로젝트 멤버에게 알림이 전송된다.
3. 완료된 태스크는 Done 컬럼에 표시되며 통계에 반영된다.

### 시나리오 5 — 대시보드 통계 확인
1. 프로젝트 대시보드에서 전체 태스크 수, 완료율, 멤버별 할당 현황을 확인한다.
2. 기간별 완료 추이를 차트로 확인한다.

## 4. 기능 요구사항

### 4.1 인증

- **FR-01**: 이메일/비밀번호 기반 회원가입을 제공한다. 비밀번호는 최소 8자 이상이어야 한다.
- **FR-02**: 회원가입 시 이메일 인증 링크를 발송한다. 인증 완료 전에는 로그인할 수 없다.
- **FR-03**: 로그인 성공 시 JWT 액세스 토큰(1시간)과 리프레시 토큰(7일)을 발급한다.
- **FR-04**: 리프레시 토큰으로 액세스 토큰을 갱신할 수 있다.

### 4.2 프로젝트 관리

- **FR-05**: 프로젝트를 생성할 수 있다. 이름(필수, 최대 100자)과 설명(선택, 최대 500자)을 입력한다.
- **FR-06**: 프로젝트 생성자는 자동으로 Owner 역할을 부여받는다.
- **FR-07**: Owner는 이메일 주소로 멤버를 초대할 수 있다. 초대받은 사용자에게 알림이 전송된다.
- **FR-08**: 프로젝트 목록을 조회할 수 있으며, 자신이 속한 프로젝트만 표시된다.

### 4.3 태스크 관리

- **FR-09**: 프로젝트 내에서 태스크를 생성할 수 있다. 제목(필수), 설명(선택), 우선순위(Low/Medium/High, 기본값 Medium), 마감일(선택)을 입력한다.
- **FR-10**: 태스크를 프로젝트 멤버에게 할당할 수 있다. 할당 시 해당 멤버에게 알림이 전송된다.
- **FR-11**: 태스크 상태를 Todo/In Progress/Done으로 변경할 수 있다. 상태 변경 시 프로젝트 멤버에게 알림이 전송된다.
- **FR-12**: 태스크를 삭제할 수 있다. 삭제는 프로젝트 Owner 또는 태스크 생성자만 가능하다.
- **FR-13**: 프로젝트별 태스크 목록을 상태·우선순위·할당자 기준으로 필터링하여 조회할 수 있다.

### 4.4 알림

- **FR-14**: 태스크 할당, 상태 변경, 프로젝트 초대 시 대상 사용자에게 인앱 알림을 생성한다.
- **FR-15**: 읽지 않은 알림 수를 헤더에 표시한다.
- **FR-16**: 알림 목록을 조회하고, 개별 또는 전체 읽음 처리할 수 있다.

### 4.5 대시보드

- **FR-17**: 프로젝트별 태스크 진행률(완료/전체)을 표시한다.
- **FR-18**: 멤버별 할당 태스크 수와 완료 태스크 수를 표시한다.

## 5. 비기능 요구사항

### 성능
- **NFR-01**: 태스크 목록 조회는 500ms 이내에 응답해야 한다.
- **NFR-02**: 알림 생성은 비동기로 처리하여 태스크 작업의 응답 시간에 영향을 주지 않아야 한다.

### 보안
- **NFR-03**: 비밀번호는 bcrypt로 해시하여 저장한다.
- **NFR-04**: JWT 비밀키는 환경 변수로 관리하며 소스 코드에 포함하지 않는다.
- **NFR-05**: 프로젝트 데이터는 해당 프로젝트의 멤버만 접근할 수 있다.

### 사용성
- **NFR-06**: 칸반 보드는 드래그앤드롭으로 태스크 상태를 변경할 수 있어야 한다.
- **NFR-07**: 모든 에러 상황에서 사용자가 이해할 수 있는 메시지를 표시한다.

## 6. 제약사항 및 리스크

| 구분 | 내용 |
|------|------|
| **실시간 알림** | 인앱 알림은 폴링 또는 WebSocket으로 구현 가능. 초기 버전은 폴링으로 시작하고 필요 시 WebSocket으로 전환. |
| **이메일 발송** | 이메일 인증 및 초대에 외부 이메일 서비스(SendGrid 등)가 필요. 개발 환경에서는 콘솔 출력으로 대체. |
| **권한 모델** | 현재 Owner/Member 2단계만 지원. 향후 역할 확장(Admin, Viewer 등) 시 권한 체계 재설계 필요. |

## 7. 기술 고려사항

### 기술 스택

| 영역 | 기술 |
|------|------|
| Backend | Node.js + Express |
| Database | PostgreSQL |
| Cache / Queue | Redis |
| Frontend | React + TypeScript |
| 인증 | JWT (Access + Refresh Token) |

### API 구조

| 리소스 | 엔드포인트 | 인증 |
|--------|-----------|------|
| Auth | POST /api/auth/register, POST /api/auth/login, POST /api/auth/refresh | 없음 |
| Projects | GET/POST /api/projects, GET /api/projects/:id | JWT |
| Tasks | GET/POST /api/projects/:id/tasks, PATCH/DELETE /api/tasks/:id | JWT |
| Notifications | GET /api/notifications, PATCH /api/notifications/:id/read | JWT |
