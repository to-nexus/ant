One runtime underneath projectType decides policy, never layout
The same four processes, the same Redis bus, the same agent loop. A project's kind decides which jobs it exposes — it never forks the code path.

Chosen once, at creation. A project is one kind or the other for life, and the partition is strict — no job type runs in both. Adding a custom job to a workspace is a file operation, not a code change.
