One system, four backend processes

Every process talks over Redis and nothing else. There is no second code path.

Browser
ant-ui
React SPA — task board, agent chat, artifact viewer, browser IDE
ant-site
Marketing and documentation surface
one HTTP + SSE edge
Services
ant-api
REST, auth, git and worktrees, IDE orchestration
ant-realtime
Server-sent events — job state, workflow graph, logs
ant-preview
Runs and proxies each feature's dev server
Redis Pub/Sub · BullMQ · state store the only channel between processes
ant-job
Dequeues work and supervises it to completion or interruption
job-runner
One isolated child process per job, running the agent graph
Optional
sidecars
ChromaDB
Vector index for codebase retrieval — off by default
visual-processor
Image operations for the visual job

The same topology everywhere. Local runs every process on one machine; cloud runs them as pods. One data plane, no in-memory fallbacks — so what works on your laptop works in production.
