## Art Perspective: 3D

**Activation gate**: `gameArtTier.perspective === '3d'`.

### Camera

A 3D project commits one of three sub-views explicitly:

| Sub-view | Description |
|---|---|
| **3D first-person** | Camera at the player's eye. Used for FPS, exploration, immersive sims. |
| **3D third-person** | Camera follows the player from behind / over-the-shoulder. Used for action-adventure, RPGs. |
| **3D fixed / orbit** | Camera mounted on a fixed track or orbits a target (chess view, cinematic puzzles). |

Field-of-view, follow distance, and camera collision (does the camera clip through walls?) are committed in this slot — they are perspective-defining decisions, not balancing.

### Depth handling

- **Depth buffer** — hardware z-buffer. No manual layer sort.
- **LOD (level of detail)** — distant geometry switches to lower-poly representations. Phase 4 hook (Phase 3 minimum is procedural shapes only — 3D in Phase 3 is rare).
- **Frustum culling** — geometry outside the camera's view is skipped. Engine-handled.
- **Transparency / alpha sort** — translucent entities require manual sort or alpha-tested rendering. Engine partial commits the choice.

### Input ↔ camera mapping

| Sub-view | Typical input mapping |
|---|---|
| 3D first-person | Mouse / right-stick = look (yaw + pitch). WASD / left-stick = world-relative move. |
| 3D third-person | Mouse / right-stick = orbit camera. WASD / left-stick = camera-relative move. |
| 3D fixed / orbit | Input rarely controls camera; camera follows scripted track. |

Camera-relative vs world-relative movement is a category-defining decision — commit early.

### Asset implications

- Models are mesh-based (`.glb`, `.gltf`, `.fbx`). 2D sprites are out of place except for billboards / VFX.
- Texture pipeline is more involved — diffuse / normal / roughness / metallic (PBR) or simpler diffuse-only.
- Animation rigs (skeletons, blend shapes) are mandatory for character work.
- Audio benefits from 3D positioning (sound source distance, falloff) — engine-specific API.

In Phase 3 minimum scope, **3D projects are rare**. The Phaser engine partial does not cover 3D; using `perspective === '3d'` with `gameEngine === 'phaser'` is a category mismatch.

### Code-time consequences

- The engine partial (techTier × gameEngine) supplies the 3D API. In Phase 3, only Phaser has a body, and Phaser is 2D-only.
- 3D projects MUST surface engine choice as an open question in Phase 3 — Godot / Cocos / Three.js / Unity (Phase 4+) is the natural pairing.
- Asset catalog `kind: 'inline'` is rarely usable — 3D assets are almost always `kind: 'external'`.

### Blind-spot reminders

- ⚠️ **Camera collision** (clipping through walls) is the #1 cinematic failure mode in third-person 3D. Commit a policy (push back, fade target, free orbit).
- ⚠️ **Motion sickness** in first-person — head-bob, FOV changes, snap rotation. Commit accessibility defaults.
- ⚠️ **3D in Phase 3** with `gameEngine === 'phaser'` is a contradiction. Surface as an open question rather than fabricating WebGL code.
